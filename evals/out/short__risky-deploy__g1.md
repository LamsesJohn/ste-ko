네, 문제가 있습니다. 2단계가 실패하면 서버에 실행할 앱이 남지 않습니다.

**확인한 문제** (절차 설명만 보고 판단했습니다)

| 문제 | 결과 |
|---|---|
| 복사 전에 삭제 | 복사가 끝날 때까지 서비스가 중단됩니다 |
| 실행 중에 삭제 | 실행 중인 프로세스가 없어진 파일을 읽다 오류가 납니다 |
| 복사 도중 중단 | 일부 파일만 새 버전인 상태가 됩니다 |
| 재시작 실패 | 이전 버전이 없어 롤백할 수 없습니다 |

**확인하지 못한 것**

1. `/srv/app` 안에 업로드 파일, 설정, DB 파일 같은 영구 데이터가 있는지 모릅니다. 있다면 1단계에서 모두 사라집니다.
2. 서비스를 systemd로 관리하는지 모릅니다.

**권장 절차**

1. 새 버전을 `/srv/releases/<버전>` 에 복사한다.
2. 복사한 파일이 완전한지 점검한다.
3. 임시 링크를 만든다. `ln -sfn /srv/releases/<버전> /srv/app.new`
4. 링크를 원자적으로 교체한다. `mv -T /srv/app.new /srv/app`
5. 서비스를 재시작한다.
6. 실패하면 링크를 이전 릴리스로 되돌리고 다시 재시작한다.
7. 오래된 릴리스는 최근 몇 개만 남기고 지운다.

`/srv/app` 이 지금 일반 디렉터리라면 링크로 바꾸는 이전 작업을 한 번 해야 합니다. 영구 데이터는 `/srv/shared` 같은 별도 경로로 분리하세요.

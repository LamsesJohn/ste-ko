먼저 프록시 뒤에 있는 애플리케이션 서버가 살아 있는지 확인하십시오. 502는 Nginx 같은 프록시가 애플리케이션 서버에서 올바른 응답을 받지 못했다는 뜻입니다.

1. 애플리케이션 프로세스 상태를 확인합니다. `systemctl status <서비스명>` 또는 `docker ps`를 실행합니다.
2. 애플리케이션이 프록시가 보는 포트에서 대기하는지 확인합니다. `ss -tlnp | grep <포트>`를 실행합니다.
3. 프록시를 거치지 않고 애플리케이션에 직접 요청합니다. `curl -i http://127.0.0.1:<포트>/`를 실행합니다.
4. 프록시 오류 로그를 읽습니다. Nginx는 보통 `/var/log/nginx/error.log`에 있습니다. `connect() failed`나 `upstream prematurely closed connection`이 원인을 알려 줍니다.
5. 애플리케이션 로그에서 같은 시각의 충돌, 메모리 부족(OOM), 타임아웃을 찾습니다.
6. 프록시 설정의 upstream 주소와 포트가 실제 값과 같은지 확인합니다.

직접 요청(3번)이 성공하고 프록시를 거치면 실패하면, 원인은 프록시 설정이나 타임아웃일 가능성이 큽니다. 직접 요청도 실패하면 애플리케이션 쪽 문제입니다.

사용하는 프록시와 배포 방식(systemd, Docker, Kubernetes)을 알려 주시면 해당 환경에 맞는 명령으로 좁혀 드리겠습니다.

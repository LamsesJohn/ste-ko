네, 문제가 있습니다. 2단계가 실패하면 앱이 없는 상태로 남고 복구할 방법도 없습니다.

확인한 범위는 말씀하신 세 단계의 설명뿐입니다. 실제 스크립트와 서버 구성은 보지 못했습니다.

**문제점**

| 문제 | 영향 |
|---|---|
| 삭제와 복사 사이에 앱이 없음 | 서비스가 실행 중이면 요청이 실패할 수 있음 |
| 복사 실패 시 롤백 불가 | 이전 버전이 이미 지워져 있음 |
| `/srv/app` 안의 설정, 업로드, 데이터가 함께 삭제됨 | 해당 파일이 거기 있다면 영구 손실 |
| `rm -rf`에 변수를 쓰는 경우 | 변수가 비면 의도하지 않은 경로가 삭제될 수 있음 |
| 재시작 전까지 새 파일과 실행 중인 프로세스가 불일치 | 일시적인 오류 가능 |

위 표의 마지막 두 항목은 일반적인 위험이고, 실제로 발생하는지는 확인하지 못했습니다.

**권장 절차 (릴리스 디렉터리와 심볼릭 링크 교체)**

1. 새 버전을 `/srv/releases/<버전>`에 복사한다.
2. 설정과 데이터는 `/srv/shared`에 두고 릴리스에 링크한다.
3. 임시 링크를 만든다. `ln -sfn /srv/releases/<버전> /srv/app.new`
4. 링크를 원자적으로 교체한다. `mv -T /srv/app.new /srv/app`
5. 서비스를 재시작한다.
6. 상태 확인에 실패하면 링크를 이전 릴리스로 되돌린다.
7. 오래된 릴리스는 최근 3~5개만 남기고 삭제한다.

처음 한 번은 기존 `/srv/app` 디렉터리를 `/srv/releases/<현재버전>`으로 옮기고 링크로 바꿔야 합니다.

스크립트 상단에 `set -euo pipefail`을 넣으면 중간 실패 시 즉시 중단됩니다. 스크립트를 보여주시면 구체적으로 검토하겠습니다.

merge는 두 브랜치의 히스토리를 그대로 보존하며 합치고, rebase는 내 커밋을 대상 브랜치 끝으로 옮겨 히스토리를 일직선으로 만듭니다.

| 항목 | merge | rebase |
|---|---|---|
| 히스토리 | 분기와 합류가 그대로 남음 | 일직선으로 정리됨 |
| 새 커밋 | 머지 커밋이 하나 생김 | 머지 커밋이 생기지 않음 |
| 기존 커밋 | 해시가 바뀌지 않음 | 새 해시로 다시 만들어짐 |
| 충돌 해결 | 한 번에 해결함 | 커밋마다 해결할 수 있음 |
| 되돌리기 | 머지 커밋 하나를 revert하면 됨 | reflog로 복구해야 함 |
| 공유 브랜치 | 안전함 | 위험함 |

**동작 방식**

1. merge는 두 브랜치의 끝을 가리키는 머지 커밋을 만듭니다.
2. rebase는 내 브랜치의 커밋을 임시로 떼어냅니다.
3. rebase는 대상 브랜치 끝에 그 커밋을 하나씩 다시 적용합니다.

**사용 기준**

- 이미 push해서 다른 사람이 쓰는 브랜치에는 merge를 씁니다.
- 아직 공유하지 않은 내 로컬 브랜치를 최신 main 위로 정리할 때는 rebase를 씁니다.
- 공유한 브랜치를 rebase한 뒤에는 force push가 필요해서 협업자의 히스토리가 꼬일 수 있습니다.

**명령어**

```bash
# merge: main에서 feature를 합침
git switch main
git merge feature

# rebase: feature를 main 위로 옮김
git switch feature
git rebase main
```

팀에서 정한 규칙이 있다면 그 규칙을 우선합니다.

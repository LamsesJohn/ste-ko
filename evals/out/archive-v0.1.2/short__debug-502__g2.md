업스트림 앱 프로세스가 살아 있는지 먼저 확인하세요. 502는 프록시(Nginx, ALB 등)가 뒤쪽 앱에서 정상 응답을 받지 못했다는 뜻입니다. 아직 이 환경의 서버는 확인하지 않았습니다. 아래는 일반적인 순서입니다.

1. 앱 프로세스 상태를 확인합니다. `systemctl status <앱>` 또는 `docker ps`를 씁니다.
2. 앱이 포트에서 응답하는지 확인합니다. `curl -i http://127.0.0.1:<포트>/`를 씁니다.
3. 프록시 에러 로그를 확인합니다. `tail -n 100 /var/log/nginx/error.log`를 씁니다.
4. 앱 로그에서 크래시, OOM, 예외를 찾습니다. `journalctl -u <앱> -n 200`을 씁니다.
5. 프록시 설정의 업스트림 주소와 포트를 확인합니다. `nginx -t`로 설정 오류도 검사합니다.
6. 최근 배포나 설정 변경이 있었는지 확인합니다.

에러 로그 문구로 원인을 좁힐 수 있습니다.

| 로그 문구 | 가능한 원인 |
|---|---|
| `connect() failed (111: Connection refused)` | 앱이 죽었거나 포트가 다릅니다 |
| `upstream prematurely closed connection` | 앱이 요청 처리 중 크래시했습니다 |
| `upstream timed out` | 앱 응답이 느리거나 타임아웃 값이 짧습니다 |
| `no live upstreams` | 모든 백엔드가 헬스체크에 실패했습니다 |

에러 로그 몇 줄과 사용 중인 프록시 종류를 알려주시면 원인을 더 좁히겠습니다. 서버가 이 작업 디렉터리에 있다면 제가 직접 설정과 로그를 읽을 수도 있습니다.

리버스 프록시 뒤에 있는 업스트림 앱 프로세스가 살아 있는지부터 확인하세요. 502는 프록시가 업스트림에서 올바른 응답을 받지 못했다는 뜻입니다.

저는 아직 사용자 서버를 직접 확인하지 못했습니다. 아래는 일반적인 순서입니다.

1. 앱 프로세스 상태를 확인합니다. `systemctl status <앱 서비스>` 또는 `docker ps`를 실행합니다.
2. 업스트림에 직접 요청합니다. `curl -i http://127.0.0.1:<포트>/`를 실행합니다.
3. 프록시 에러 로그를 봅니다. nginx는 `/var/log/nginx/error.log`입니다.
4. 앱 로그에서 크래시, 메모리 부족, 예외를 찾습니다. `journalctl -u <앱 서비스> -n 200`을 실행합니다.
5. 프록시 설정의 업스트림 주소와 포트가 실제 앱과 일치하는지 대조합니다.
6. 최근 배포나 설정 변경이 있었는지 확인합니다.

에러 로그 문구로 원인을 좁힐 수 있습니다.

| 로그 문구 | 의심 원인 |
|---|---|
| `connect() failed (111: Connection refused)` | 앱이 꺼졌거나 포트가 다름 |
| `upstream prematurely closed connection` | 앱이 요청 처리 중 크래시함 |
| `upstream timed out` | 앱 응답이 느리거나 멈춤 |
| `no live upstreams` | 모든 업스트림이 헬스 체크에 실패함 |

프록시 종류, 에러 로그 한 줄, 앱 실행 방식을 알려주시면 원인을 더 좁혀 드리겠습니다.

문제가 있습니다. 현재 절차는 2단계가 실패하면 서버에 실행할 앱이 남지 않습니다. 저는 실제 서버와 배포 스크립트를 확인하지 못했고, 아래 내용은 적어주신 3단계만 근거로 했습니다.

| 문제 | 영향 |
|---|---|
| 삭제 후 복사 | 복사가 실패하면 앱이 사라지고 복구할 버전이 없습니다. |
| 삭제와 재시작 사이 공백 | 이 시간 동안 실행 중인 서비스가 삭제된 파일을 참조합니다. |
| 롤백 수단 없음 | 새 버전에 결함이 있어도 이전 버전으로 되돌릴 수 없습니다. |
| /srv/app 안의 데이터 삭제 | 설정 파일, 업로드 파일, SQLite 같은 로컬 데이터가 있으면 함께 사라집니다. |
| 변수 경로 사용 시 위험 | 스크립트에서 경로를 변수로 쓰면 값이 비었을 때 엉뚱한 경로를 지울 수 있습니다. |

릴리스 디렉터리와 심볼릭 링크 방식을 권장합니다.

1. 새 버전을 /srv/releases/<버전>에 복사한다.
2. 설정과 데이터는 /srv/shared에 두고 각 릴리스에 링크한다.
3. 새 릴리스에서 설정 검증이나 헬스체크를 실행한다.
4. `ln -sfn /srv/releases/<버전> /srv/app.tmp && mv -T /srv/app.tmp /srv/app`으로 링크를 교체한다.
5. 서비스를 재시작한다.
6. 헬스체크가 실패하면 링크를 이전 릴리스로 되돌리고 다시 재시작한다.
7. 최근 5개를 제외한 릴리스를 삭제한다.

이 방식은 복사가 실패해도 기존 버전이 그대로 남습니다. 롤백은 링크 교체와 재시작 두 동작으로 끝납니다.

/srv/app에 로컬 데이터가 있는지 알려주시면 공유 디렉터리 구성을 구체적으로 제안하겠습니다.

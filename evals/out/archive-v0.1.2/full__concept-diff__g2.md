둘 다 한 브랜치의 변경을 다른 브랜치에 합칩니다. 차이는 커밋 히스토리의 모양입니다. merge는 기존 히스토리를 보존하고, rebase는 히스토리를 다시 씁니다.

## merge

`git merge main`은 두 브랜치를 잇는 병합 커밋을 새로 만듭니다. 기존 커밋은 바뀌지 않습니다. 히스토리에 분기와 합류가 그대로 남습니다.

```
A---B---C---M   (feature)
     \     /
      D---E     (main)
```

## rebase

`git rebase main`은 내 브랜치의 커밋을 main의 최신 커밋 뒤로 옮겨 다시 만듭니다. 커밋 해시가 바뀝니다. 히스토리가 한 줄이 됩니다.

```
A---B---D---E---C'   (feature)
```

## 비교

| 항목 | merge | rebase |
|---|---|---|
| 기존 커밋 | 유지 | 새 해시로 다시 생성 |
| 히스토리 | 분기가 보임 | 한 줄 |
| 병합 커밋 | 생김 | 생기지 않음 |
| 충돌 해결 | 한 번 | 커밋마다 필요할 수 있음 |
| 되돌리기 | 쉬움 | 상대적으로 어려움 |

## 선택 기준

- 이미 push해서 다른 사람이 쓰는 브랜치에는 rebase하지 않습니다. 해시가 바뀌어 다른 사람의 히스토리와 어긋납니다.
- 내 로컬 브랜치를 최신 main에 맞출 때는 rebase를 씁니다.
- 공유 브랜치에 합칠 때는 merge를 씁니다.
- 팀이 정한 규칙이 있으면 그 규칙을 따릅니다.

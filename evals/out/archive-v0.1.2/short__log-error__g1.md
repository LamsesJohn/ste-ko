테스트가 접속하려는 주소와 포트에서 서버가 듣고 있지 않아서 실패했습니다.

아직 코드와 전체 트레이스백을 확인하지 못했습니다. 아래 내용은 이 오류의 일반적인 원인입니다.

| 가능한 원인 | 확인 방법 |
|---|---|
| 테스트 대상 서버가 실행되지 않음 | `ss -ltnp`로 해당 포트의 리스너를 확인합니다 |
| DB, Redis 같은 외부 서비스가 꺼져 있음 | 서비스 상태나 `docker ps`를 확인합니다 |
| 포트 번호나 호스트 설정이 틀림 | 환경변수와 설정 파일의 값을 확인합니다 |
| 서버가 시작되기 전에 테스트가 접속함 | 서버 기동 대기 로직이 있는지 확인합니다 |
| WSL2나 컨테이너에서 `localhost`가 다른 대상을 가리킴 | 호스트 주소를 `127.0.0.1`이나 서비스 이름으로 바꿔 봅니다 |

다음 순서로 진단하면 됩니다.

1. 트레이스백에서 접속을 시도한 호스트와 포트를 찾습니다.
2. 그 포트에서 프로세스가 듣고 있는지 확인합니다.
3. 듣고 있지 않으면 해당 서비스를 먼저 실행합니다.
4. 듣고 있으면 테스트가 쓰는 주소 설정을 확인합니다.

전체 트레이스백과 실패한 테스트 파일 경로를 알려 주시면 정확한 원인을 좁히겠습니다. 원하시면 작업 디렉터리에서 접속 설정을 직접 검색하겠습니다.

merge는 두 브랜치의 이력을 병합 커밋으로 합치고, rebase는 내 커밋을 대상 브랜치 끝으로 옮겨 이력을 일직선으로 만듭니다.

| 구분 | merge | rebase |
|---|---|---|
| 이력 모양 | 분기와 병합이 그대로 남음 | 일직선 |
| 새 커밋 | 병합 커밋 1개 생성 | 병합 커밋 없음 |
| 기존 커밋 | 해시가 바뀌지 않음 | 해시가 바뀌며 새 커밋으로 다시 만들어짐 |
| 충돌 해결 | 한 번에 해결 | 커밋마다 해결 |
| 안전성 | 공유 브랜치에도 안전 | 공유 브랜치에는 위험 |
| 되돌리기 | 병합 커밋 하나를 revert | 이력이 다시 쓰여 복구가 어려움 |

**merge 사용법**

1. `git switch main`으로 합칠 대상 브랜치로 이동합니다.
2. `git merge feature`를 실행합니다.

**rebase 사용법**

1. `git switch feature`로 내 브랜치로 이동합니다.
2. `git rebase main`을 실행합니다.
3. 필요하면 `git switch main`과 `git merge feature`로 fast-forward 병합합니다.

**선택 기준**

- 이미 push해서 다른 사람이 쓰는 브랜치는 merge를 씁니다.
- 아직 push하지 않은 내 로컬 브랜치는 rebase로 정리합니다.
- 실제 분기 이력을 보존해야 하면 merge를 씁니다.
- 읽기 쉬운 선형 이력이 목표라면 rebase를 씁니다.

공유된 브랜치를 rebase하면 이력이 달라져서 `git push --force`가 필요해지고, 다른 팀원의 작업과 충돌합니다. 이 점이 가장 큰 주의사항입니다.

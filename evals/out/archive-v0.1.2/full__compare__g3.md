Docker 컨테이너는 호스트 OS의 커널을 공유해 가볍고 빠릅니다. 가상 머신(VM)은 게스트 OS를 통째로 실행해 더 강하게 격리됩니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트 커널을 공유합니다 | 게스트마다 자기 커널을 가집니다 |
| 격리 수준 | 프로세스 단위입니다 | 하드웨어 가상화 단위입니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 보통 수십 초에서 수 분입니다 |
| 이미지 크기 | 수십 MB에서 수백 MB입니다 | 수 GB입니다 |
| 자원 사용 | 앱이 쓰는 만큼만 씁니다 | OS마다 CPU와 메모리를 미리 할당합니다 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 가능합니다 | 어떤 OS든 가능합니다 |
| 보안 경계 | 커널 취약점의 영향을 받습니다 | 더 강한 경계를 제공합니다 |
| 주 용도 | 마이크로서비스, CI, 배포 단위 | 서버 통합, 다른 OS 필요, 강한 격리 필요 |

## 선택 기준

- 앱을 빠르게 배포하고 같은 환경을 재현하려면 Docker를 씁니다.
- Windows 앱을 Linux 호스트에서 실행하는 것처럼 다른 커널이 필요하면 VM을 씁니다.
- 서로 신뢰하지 않는 사용자의 코드를 실행하면 VM을 씁니다. 컨테이너는 커널을 공유하므로 탈출 취약점의 위험이 있습니다.
- 둘을 함께 쓰는 경우도 많습니다. 클라우드에서는 VM 위에서 컨테이너를 실행합니다.

Windows와 macOS의 Docker Desktop은 내부에서 경량 VM을 실행합니다. 이 환경에서는 컨테이너도 VM 위에서 돌아갑니다.

둘 다 한 브랜치의 변경을 다른 브랜치에 가져오는 명령이다. merge는 히스토리를 그대로 두고 합치고, rebase는 내 커밋을 다시 만들어 히스토리를 일직선으로 만든다.

| | merge | rebase |
|---|---|---|
| 동작 | 두 브랜치를 잇는 병합 커밋을 만든다 | 내 커밋을 대상 브랜치 끝에 다시 쌓는다 |
| 히스토리 | 갈라지고 합쳐진 흔적이 남는다 | 일직선이 된다 |
| 기존 커밋 | 바뀌지 않는다 | 해시가 바뀐다. 새 커밋이 생긴다 |
| 충돌 해결 | 한 번 해결한다 | 커밋마다 해결할 수 있다 |
| 되돌리기 | 병합 커밋 하나를 되돌린다 | 이전 상태로 복구하기 어렵다 |

## 명령 예

`feature` 브랜치에서 `main`의 변경을 가져오는 경우다.

```bash
# merge
git switch feature
git merge main

# rebase
git switch feature
git rebase main
```

## 선택 기준

- 이미 push해서 다른 사람이 쓰는 브랜치에는 rebase를 쓰지 않는다. 커밋 해시가 바뀌어서 다른 사람의 히스토리와 충돌한다.
- 내 로컬 브랜치를 정리할 때는 rebase를 쓴다. 히스토리가 읽기 쉬워진다.
- 공유 브랜치(`main` 등)에 기능 브랜치를 합칠 때는 merge를 쓴다. 누가 언제 합쳤는지 기록이 남는다.

팀이 정한 규칙이 있으면 그 규칙을 따른다. 팀마다 "squash merge만 허용" 또는 "rebase 후 fast-forward만 허용"처럼 정책이 다르다.

Docker는 호스트 OS의 커널을 공유하는 가벼운 격리 방식이고, 가상 머신(VM)은 OS 전체를 따로 실행하는 강한 격리 방식이에요.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 프로세스 | 하드웨어 전체 |
| 커널 | 호스트와 공유 | VM마다 별도 |
| 시작 시간 | 보통 1초 안팎 | 보통 수십 초에서 수 분 |
| 크기 | 수십 MB에서 수백 MB | 수 GB 이상 |
| 자원 사용 | 적음 | 많음 (OS마다 메모리와 CPU 사용) |
| 보안 격리 | 상대적으로 약함 | 강함 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 가능 | 가능 (예: Linux 위에서 Windows) |

## 언제 무엇을 쓰나요

- 같은 앱을 여러 개 빠르게 띄우거나 배포할 때는 Docker를 써요.
- 개발 환경과 운영 환경을 똑같이 맞출 때도 Docker가 편해요.
- 신뢰할 수 없는 코드를 실행하거나 서로 다른 고객의 환경을 분리할 때는 VM을 써요.
- 호스트와 다른 OS나 커널이 필요하면 VM을 써요.

## 함께 쓰는 경우

클라우드에서는 VM 위에서 Docker를 실행하는 구성이 흔해요. VM이 강한 격리를 맡고, 컨테이너가 앱 배포를 맡아요. macOS와 Windows의 Docker Desktop도 내부에서 작은 Linux VM을 실행해요.

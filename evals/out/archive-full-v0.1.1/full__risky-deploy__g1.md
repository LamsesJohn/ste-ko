응, 문제 있어. 새 버전을 복사하기 전에 이전 버전을 지워서, 복사가 실패하면 실행할 앱도 되돌릴 버전도 없어.

**문제**
1. 롤백이 불가능해. 2단계가 실패하면 복구할 파일이 없어.
2. 중단 시간이 길어. 1단계부터 3단계까지 서비스가 깨진 상태야.
3. 실행 중인 서비스의 파일을 지워. 서비스가 파일을 열어 둔 채 오류를 낼 수 있어.
4. `/srv/app` 아래에 설정, 업로드 파일, 데이터가 있으면 같이 지워져.
5. 재시작이 성공했는지 확인하는 단계가 없어.

**권장 절차**
1. 새 버전을 `/srv/app/releases/<버전>`에 복사한다.
2. 심볼릭 링크를 바꾼다. `ln -sfn /srv/app/releases/<버전> /srv/app/current`
3. 서비스를 재시작한다.
4. 상태 확인 요청이 성공하는지 확인한다.
5. 확인이 실패하면 링크를 이전 버전으로 되돌리고 다시 재시작한다.
6. 최근 3~5개 릴리스만 남기고 오래된 릴리스를 지운다.

설정과 데이터는 `releases` 밖에 두면 배포 때 건드리지 않아. 서비스 설정의 실행 경로는 `/srv/app/current`로 바꿔야 해.

`rm -rf`를 꼭 써야 하면 변수를 쓰지 말고 경로를 고정해. 6단계의 삭제 대상은 `releases` 안으로 한정해.

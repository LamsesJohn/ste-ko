**Docker는 호스트 OS의 커널을 공유하고, 가상 머신은 자기 OS를 통째로 실행해요.** 그래서 Docker는 가볍고 빠르며, 가상 머신은 격리가 더 강해요.

가상 머신(VM)은 하이퍼바이저가 만든 가상 하드웨어 위에서 게스트 OS를 실행해요. 하이퍼바이저는 가상 하드웨어를 만들고 나눠 주는 소프트웨어예요. Docker 컨테이너는 호스트 커널 위에서 격리된 프로세스로 실행돼요. 커널은 OS의 핵심 부분이에요.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트와 공유 | VM마다 따로 가짐 |
| 시작 시간 | 보통 1초 안팎 | 보통 수십 초에서 몇 분 |
| 이미지 크기 | 수십~수백 MB | 보통 수 GB |
| 메모리 사용 | 앱이 쓰는 만큼 | 게스트 OS 몫이 추가됨 |
| 격리 강도 | 커널 수준 격리 | 하드웨어 수준 격리 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 가능 | 가능 (예: Linux 호스트에서 Windows) |
| 주 용도 | 앱 배포, 마이크로서비스, CI | 서버 통합, 다른 OS 실행, 강한 격리 |

**Docker를 고를 때**
- 앱을 같은 환경으로 빠르게 배포하고 싶을 때
- 한 서버에 많은 서비스를 올릴 때

**VM을 고를 때**
- 신뢰할 수 없는 코드나 여러 고객의 워크로드를 분리해야 할 때
- 호스트와 다른 OS나 커널이 필요할 때

두 방식은 함께 쓰는 경우가 많아요. 클라우드에서는 VM 안에서 컨테이너를 실행해 두 장점을 합쳐요. 지금 환경인 WSL2도 가벼운 VM 안에서 Linux 커널을 돌려요. Windows에서 Docker가 동작하는 이유예요.

Docker는 호스트 OS의 커널을 공유하고, 가상 머신(VM)은 게스트 OS를 통째로 실행합니다. 그래서 Docker가 더 가볍고 빠르며, VM이 더 강하게 격리됩니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트 커널을 공유합니다 | 게스트마다 자체 커널을 가집니다 |
| 격리 수준 | 프로세스 단위로 격리합니다 | 하드웨어 수준으로 격리합니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 보통 수십 초에서 수 분입니다 |
| 이미지 크기 | 수십~수백 MB입니다 | 수 GB입니다 |
| 자원 사용 | 앱이 쓰는 만큼만 씁니다 | OS 전체가 쓰는 메모리와 디스크를 먼저 차지합니다 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 실행합니다 | Windows, Linux 등 어떤 OS도 실행합니다 |
| 보안 | 커널 취약점이 모든 컨테이너에 영향을 줍니다 | 한 VM이 뚫려도 다른 VM과 호스트는 상대적으로 안전합니다 |

위 시간과 크기는 일반적인 범위이며, 환경에 따라 다릅니다.

## 구조 차이

- **Docker**: 컨테이너 런타임이 리눅스 커널의 namespace와 cgroup 기능으로 프로세스를 격리합니다. namespace는 프로세스가 보는 자원을 나누고, cgroup은 CPU와 메모리 사용량을 제한합니다.
- **VM**: 하이퍼바이저가 물리 하드웨어를 가상 하드웨어로 나눕니다. 각 VM은 그 위에서 독립된 OS를 부팅합니다.

## 선택 기준

Docker를 고르는 경우:
- 같은 앱을 개발, 테스트, 운영 환경에서 똑같이 실행해야 할 때
- 마이크로서비스를 많이 띄우거나 빠르게 확장해야 할 때
- CI/CD 파이프라인에서 환경을 빠르게 만들고 지워야 할 때

VM을 고르는 경우:
- 서로 신뢰하지 않는 사용자나 워크로드를 분리해야 할 때
- 호스트와 다른 OS나 커널이 필요할 때
- 레거시 앱을 OS째로 옮겨야 할 때

## 함께 쓰는 경우

운영 환경에서는 VM 위에서 Docker를 실행하는 구성이 흔합니다. VM이 격리 경계를 맡고, Docker가 앱 배포를 맡습니다. Windows와 macOS의 Docker Desktop도 내부에서 경량 VM을 띄워 리눅스 컨테이너를 실행합니다.

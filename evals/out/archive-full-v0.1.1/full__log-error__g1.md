결론: 테스트가 접속한 주소와 포트에서 받는 프로세스가 없어. 서버가 꺼져 있거나, 주소나 포트가 틀렸어.

Errno 111은 대상 호스트에는 닿았는데 해당 포트가 닫혀 있다는 뜻이야. 방화벽이나 타임아웃 문제가 아니야.

로그만으로는 어떤 서비스에 접속했는지 몰라. 원인 후보는 이 순서로 확인해.

1. 테스트가 쓰는 DB, Redis, API 서버 같은 의존 서비스가 실행 중인지 확인한다.
2. 테스트 설정의 호스트와 포트가 서비스의 실제 값과 같은지 확인한다.
3. Docker나 WSL을 쓰면 `localhost`가 서비스가 있는 곳을 가리키는지 확인한다. 컨테이너 안에서는 `localhost`가 컨테이너 자신이야.
4. 서비스가 `127.0.0.1`에만 바인딩했는지 확인한다.

포트를 확인하는 명령은 `ss -ltnp`야.

실패한 테스트 이름이나 전체 트레이스백을 보내주면 접속 대상을 찾아줄게. 아니면 내가 이 디렉터리에서 설정 파일을 직접 찾아볼까?

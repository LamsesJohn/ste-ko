둘 다 한 브랜치의 변경을 다른 브랜치에 합치지만, 히스토리를 남기는 방식이 다르다.

- **merge**는 두 브랜치의 히스토리를 그대로 두고 병합 커밋 하나로 잇는다.
- **rebase**는 내 커밋을 대상 브랜치의 최신 커밋 위에 다시 쌓는다.

| 항목 | merge | rebase |
|---|---|---|
| 히스토리 모양 | 갈라졌다 합쳐지는 그래프 | 일직선 |
| 기존 커밋 | 바뀌지 않는다 | 새 해시로 다시 만들어진다 |
| 병합 커밋 | 생긴다 | 생기지 않는다 |
| 충돌 해결 | 한 번에 해결한다 | 커밋마다 해결할 수 있다 |
| 이미 push한 브랜치 | 안전하다 | 위험하다 |

## 명령

```bash
# merge: main에서 feature를 합친다
git switch main
git merge feature

# rebase: feature를 main의 최신 커밋 위로 옮긴다
git switch feature
git rebase main
```

## 선택 기준

- 다른 사람이 이미 가져간 브랜치(공유 브랜치)에는 merge를 쓴다. rebase는 커밋 해시를 바꾸기 때문에 팀원의 히스토리와 어긋난다.
- 아직 push하지 않은 내 로컬 브랜치를 정리할 때는 rebase를 쓴다. 히스토리가 깔끔해진다.
- 병합 시점과 브랜치 이력을 기록으로 남기고 싶으면 merge를 쓴다.

**이미 공유한 커밋은 rebase하지 않는다.** 꼭 해야 하면 팀원에게 알리고, push할 때 `git push --force-with-lease`를 쓴다.

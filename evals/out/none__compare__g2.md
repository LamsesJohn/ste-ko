# Docker(컨테이너) vs 가상 머신(VM)

## 핵심 차이
- **VM**: 하이퍼바이저가 하드웨어를 가상화하고, 각 VM이 **자체 게스트 OS(커널 포함)**를 실행합니다.
- **Docker 컨테이너**: **호스트 OS 커널을 공유**하며, namespace와 cgroup으로 프로세스를 격리합니다.

## 비교표

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 수준 | 프로세스 수준 (커널 공유) | 하드웨어 수준 (커널 분리) |
| 시작 시간 | 보통 초 단위 이하 | 수십 초~분 단위 |
| 크기 | 수 MB~수백 MB | 수 GB~수십 GB |
| 리소스 오버헤드 | 매우 낮음 | 게스트 OS 때문에 높음 |
| 성능 | 네이티브에 가까움 | 약간의 가상화 손실 |
| 보안 격리 | 상대적으로 약함 (커널 취약점 공유) | 강함 |
| OS 다양성 | 호스트와 같은 커널 계열만 (Linux 컨테이너는 Linux 커널) | Windows, Linux 등 자유롭게 혼용 |
| 이식성 | 이미지로 어디서나 동일하게 실행 | 가능하지만 이미지가 무겁다 |
| 밀도 | 한 호스트에 수백 개 가능 | 수십 개 수준 |
| 대표 도구 | Docker, Podman, containerd | VMware, VirtualBox, KVM, Hyper-V |

## 언제 무엇을 쓰나

**Docker가 적합한 경우**
- 마이크로서비스, CI/CD, 개발 환경 통일
- 빠른 배포·확장(스케일링)이 필요한 경우
- 리소스를 효율적으로 쓰고 싶을 때

**VM이 적합한 경우**
- 강한 격리가 필요한 멀티테넌트 환경, 보안이 민감한 워크로드
- 다른 OS나 커널이 필요한 경우 (예: Linux 호스트에서 Windows 실행)
- 레거시 애플리케이션, 전체 OS 단위의 제어가 필요한 경우

## 참고
- 둘은 배타적이지 않습니다. 실무에서는 **VM 위에서 컨테이너를 실행**하는 구성(예: 클라우드의 EC2 + Docker, Kubernetes 노드)이 흔합니다.
- macOS/Windows의 Docker Desktop도 내부적으로 경량 VM(또는 WSL2) 안에서 Linux 컨테이너를 돌립니다.
- Kata Containers, Firecracker 같은 **마이크로 VM** 기술은 컨테이너의 속도와 VM의 격리를 절충합니다.

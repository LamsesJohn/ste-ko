Docker는 호스트 커널을 공유하는 가벼운 격리 방식이고, 가상 머신은 하드웨어까지 가상화하는 완전한 격리 방식입니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 수준 | 프로세스 단위 격리 | 하드웨어 단위 격리 |
| 커널 | 호스트 커널 공유 | 게스트마다 별도 커널 |
| 시작 시간 | 수초 이내 | 수십 초에서 수 분 |
| 이미지 크기 | 수십 MB에서 수백 MB | 수 GB 이상 |
| 자원 사용량 | 적음 | 많음 |
| 보안 경계 | 상대적으로 약함 | 상대적으로 강함 |
| 운영체제 | 호스트와 같은 커널 계열만 사용 | 다른 운영체제도 실행 가능 |
| 이식성 | 이미지 하나로 어디서나 실행 | 하이퍼바이저에 종속되는 경우가 많음 |

**구조 차이**

1. 가상 머신은 하이퍼바이저 위에서 게스트 운영체제 전체를 실행합니다.
2. Docker는 컨테이너 런타임 위에서 애플리케이션과 라이브러리만 실행합니다.
3. 컨테이너는 리눅스의 namespace와 cgroup으로 격리와 자원 제한을 구현합니다.

**Docker가 적합한 경우**

- 마이크로서비스를 배포할 때
- CI/CD 환경을 빠르게 만들고 없앨 때
- 개발 환경을 팀원 사이에 동일하게 맞출 때

**가상 머신이 적합한 경우**

- 호스트와 다른 운영체제를 실행해야 할 때
- 신뢰할 수 없는 워크로드를 강하게 격리해야 할 때
- 커널 수준 설정이나 모듈을 직접 바꿔야 할 때

두 기술은 함께 쓰는 경우가 많습니다. 클라우드에서는 가상 머신 위에 Docker 컨테이너를 올려 격리와 효율을 모두 얻습니다.

이 비교는 일반 지식에 근거합니다. 현재 환경에서 Docker나 가상 머신을 직접 실행해 측정하지는 않았습니다.

Docker는 호스트 커널을 공유하는 가벼운 프로세스 격리이고, 가상 머신은 하이퍼바이저 위에서 커널까지 갖춘 완전한 운영체제를 실행합니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 프로세스 (namespace, cgroup) | 하드웨어 가상화 |
| 커널 | 호스트 커널 공유 | VM마다 별도 게스트 커널 |
| 이미지 크기 | 수십 MB에서 수백 MB | 수 GB 이상 |
| 시작 시간 | 수백 밀리초에서 수 초 | 수십 초에서 수 분 |
| 자원 사용 | 적음 | 많음 (OS 전체 메모리 점유) |
| 성능 | 네이티브에 가까움 | 가상화 오버헤드 있음 |
| 격리 강도 | 상대적으로 약함 (커널 공유) | 강함 (커널 분리) |
| OS 선택 | 호스트 커널과 같은 계열만 가능 | Linux, Windows 등 자유 |
| 이식성 | 이미지 한 번 빌드로 어디서나 실행 | 이미지가 크고 하이퍼바이저에 의존 |
| 대표 도구 | Docker, Podman, containerd | KVM, VMware, VirtualBox, Hyper-V |

**Docker가 적합한 경우**
1. 마이크로서비스를 빠르게 배포하고 확장할 때
2. CI/CD에서 일관된 빌드 환경이 필요할 때
3. 개발 환경을 팀 전체가 똑같이 맞출 때

**가상 머신이 적합한 경우**
1. 서로 다른 OS 커널을 함께 써야 할 때
2. 신뢰할 수 없는 워크로드를 강하게 격리해야 할 때
3. 레거시 시스템이나 전체 OS 단위 환경이 필요할 때

두 기술은 함께 쓰는 경우도 많습니다. 클라우드에서는 VM 위에 컨테이너를 올려 격리와 효율을 동시에 얻습니다.

참고로 macOS와 Windows의 Docker Desktop은 내부에서 경량 Linux VM을 실행합니다. 이 내용은 제 일반 지식에 근거하며, 현재 환경에서 직접 확인한 것은 아닙니다.

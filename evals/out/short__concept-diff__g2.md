`git merge`는 두 브랜치의 히스토리를 보존한 채 합치고, `git rebase`는 내 커밋을 대상 브랜치 끝으로 옮겨 히스토리를 한 줄로 만듭니다.

| 항목 | merge | rebase |
|---|---|---|
| 히스토리 | 분기와 합류가 그대로 남음 | 직선형으로 정리됨 |
| 새 커밋 | 머지 커밋이 생김 | 머지 커밋이 생기지 않음 |
| 기존 커밋 | 해시가 바뀌지 않음 | 새 해시로 다시 만들어짐 |
| 충돌 해결 | 한 번에 해결함 | 커밋마다 해결할 수 있음 |
| 되돌리기 | 머지 커밋 하나를 revert하면 됨 | 원래 상태로 돌리기 어려움 |
| 공유 브랜치 | 안전함 | 위험함 |

**동작 예시**

main과 feature가 갈라진 상태입니다.

```
A---B---C  main
     \
      D---E  feature
```

`git merge main`을 feature에서 실행하면 머지 커밋 M이 생깁니다.

```
A---B---C---------  main
     \           \
      D---E-------M  feature
```

`git rebase main`을 feature에서 실행하면 D, E가 C 뒤에 복제됩니다. 복제된 커밋은 D', E'로 표기합니다.

```
A---B---C  main
         \
          D'---E'  feature
```

**선택 기준**

1. 이미 push해서 다른 사람이 쓰는 브랜치에는 merge를 씁니다.
2. 아직 공유하지 않은 내 로컬 브랜치를 최신 main에 맞출 때는 rebase를 씁니다.
3. 히스토리의 실제 흐름을 남기고 싶으면 merge를 씁니다.
4. 읽기 쉬운 선형 히스토리를 원하면 rebase를 씁니다.

**주의점**

rebase는 커밋 해시를 바꿉니다. 이미 공유한 커밋을 rebase하고 push하면 `--force`가 필요하고, 다른 사람의 작업과 충돌합니다. 그래서 공유한 브랜치에는 rebase를 쓰지 않는 것이 기본 규칙입니다.

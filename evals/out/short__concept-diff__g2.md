merge는 두 브랜치의 히스토리를 보존하며 합치고, rebase는 커밋을 다른 기준점 위에 다시 쌓아 히스토리를 일직선으로 만듭니다.

| 항목 | merge | rebase |
|---|---|---|
| 히스토리 | 분기와 합류가 그대로 남음 | 일직선으로 정리됨 |
| 커밋 | 기존 커밋을 유지하고 머지 커밋을 추가함 | 커밋을 새로 만들어 해시가 바뀜 |
| 충돌 처리 | 한 번에 해결함 | 커밋마다 해결할 수 있음 |
| 안전성 | 공유 브랜치에도 안전함 | 공유 브랜치에는 위험함 |
| 되돌리기 | 머지 커밋 하나를 revert하면 됨 | 원래 상태를 복구하기 어려움 |

**merge 동작**

1. `git switch main`으로 대상 브랜치로 이동합니다.
2. `git merge feature`를 실행합니다.
3. Git이 두 브랜치의 끝을 부모로 가진 머지 커밋을 만듭니다.

**rebase 동작**

1. `git switch feature`로 작업 브랜치로 이동합니다.
2. `git rebase main`을 실행합니다.
3. Git이 feature의 커밋을 main 최신 커밋 위에 다시 적용합니다.

**선택 기준**

- 이미 push해서 다른 사람이 쓰는 브랜치에는 merge를 씁니다.
- 아직 공유하지 않은 로컬 브랜치를 정리할 때는 rebase를 씁니다.
- rebase 후 이미 push한 브랜치는 `--force-with-lease`가 필요하므로 협업 중에는 피합니다.

이 디렉터리는 git 저장소가 아니므로 위 내용은 실행해서 확인하지 않았습니다. 일반적인 Git 동작을 기준으로 설명했습니다.

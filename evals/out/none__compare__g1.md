# Docker(컨테이너) vs 가상 머신(VM)

## 핵심 차이
- **VM**: 하이퍼바이저 위에서 게스트 OS 전체(커널 포함)를 가상 하드웨어로 실행합니다.
- **Docker 컨테이너**: 호스트 OS의 커널을 공유하고, namespace·cgroup으로 프로세스를 격리해 실행합니다.

## 비교표

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 수준 | 프로세스 수준 (커널 공유) | 하드웨어 수준 (커널 분리) |
| 시작 시간 | 수백 ms ~ 수 초 | 수십 초 ~ 수 분 |
| 크기 | 수 MB ~ 수백 MB | 수 GB ~ 수십 GB |
| 리소스 오버헤드 | 매우 낮음 | 높음 (게스트 OS별 CPU·메모리 점유) |
| 성능 | 네이티브에 근접 | 가상화 오버헤드 존재 |
| 보안 | 커널 공유로 탈출 시 영향 범위가 큼 | 격리가 강해 상대적으로 안전 |
| OS 다양성 | 호스트와 같은 커널만 (Linux 컨테이너는 Linux 커널) | Windows, Linux, BSD 등 자유롭게 |
| 이식성 | 이미지 하나로 어디서나 동일 실행 | 이미지가 크고 하이퍼바이저 의존적 |
| 밀도 | 호스트 한 대에 수백 개도 가능 | 수 개 ~ 수십 개 |
| 영속성 | 기본은 일회성, 볼륨으로 데이터 유지 | 디스크 상태가 기본적으로 유지 |

## 언제 무엇을 쓸까

**Docker가 적합한 경우**
- 마이크로서비스, CI/CD, 개발 환경 표준화
- 빠른 배포·확장(스케일링)이 필요한 경우
- 같은 앱을 여러 환경에 동일하게 배포할 때

**VM이 적합한 경우**
- 서로 다른 OS가 필요할 때 (예: Linux 호스트에서 Windows 실행)
- 멀티테넌트 등 강한 격리·보안이 필요할 때
- 레거시 앱, 커널 수준 설정이 필요한 워크로드

## 참고
- 둘은 배타적이지 않습니다. 클라우드에서는 **VM 위에 컨테이너를 올리는** 구성이 흔합니다.
- Firecracker, Kata Containers 같은 **마이크로 VM**은 컨테이너의 속도와 VM의 격리를 절충합니다.
- Windows/macOS의 Docker Desktop은 내부적으로 경량 Linux VM(WSL2 등)을 사용합니다. 지금 환경(WSL2)도 그런 예입니다.

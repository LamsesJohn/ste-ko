Docker는 호스트 커널을 공유하는 가벼운 컨테이너이고, 가상 머신은 하드웨어를 가상화해 독립된 운영체제를 실행합니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 수준 | 프로세스 단위로 격리합니다 | 운영체제 단위로 완전히 격리합니다 |
| 커널 | 호스트 커널을 공유합니다 | 게스트마다 별도 커널을 씁니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 수십 초에서 수 분이 걸립니다 |
| 이미지 크기 | 수십 MB에서 수백 MB입니다 | 수 GB입니다 |
| 자원 사용량 | 적습니다 | 게스트 OS 때문에 많습니다 |
| 보안 경계 | 커널을 공유하므로 상대적으로 약합니다 | 하이퍼바이저 경계로 상대적으로 강합니다 |
| 운영체제 선택 | 호스트와 같은 커널 계열만 씁니다 | 다른 운영체제를 자유롭게 씁니다 |
| 이식성 | 이미지 하나로 어디서나 같은 환경을 재현합니다 | 이미지가 크고 하이퍼바이저에 의존합니다 |
| 주요 도구 | Docker, Podman, containerd | VMware, VirtualBox, KVM, Hyper-V |

**Docker가 적합한 경우**
1. 마이크로서비스를 배포할 때
2. CI/CD 환경을 빠르게 만들고 없앨 때
3. 개발 환경을 팀 전체가 똑같이 맞출 때

**가상 머신이 적합한 경우**
1. 서로 다른 운영체제를 함께 실행할 때
2. 신뢰할 수 없는 워크로드를 강하게 격리할 때
3. 커널 수준 설정이 필요할 때

두 기술은 함께 쓰는 경우가 많습니다. 클라우드에서는 가상 머신 위에 Docker 컨테이너를 실행하는 구성이 흔합니다.

이 설명은 일반적인 지식에 근거합니다. 현재 환경에서 Docker나 가상화 설정을 직접 확인하지는 않았습니다.

Docker는 호스트 커널을 공유하는 가벼운 컨테이너이고, 가상 머신은 하드웨어를 가상화해 게스트 OS를 통째로 실행합니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 프로세스와 파일시스템 | 하드웨어와 전체 OS |
| 커널 | 호스트 커널 공유 | 게스트마다 별도 커널 |
| 시작 시간 | 보통 1초 안팎 | 보통 수십 초에서 수 분 |
| 이미지 크기 | 수십 MB에서 수백 MB | 수 GB 이상 |
| 자원 사용 | 적음 | 많음 |
| 격리 강도 | 상대적으로 약함 | 강함 |
| OS 선택 | 호스트 커널과 호환되는 것만 가능 | 자유롭게 선택 가능 |
| 이식성 | 이미지로 배포하기 쉬움 | 이미지가 크고 하이퍼바이저에 의존 |
| 주요 도구 | Docker, containerd, Podman | KVM, VMware, VirtualBox, Hyper-V |

## 선택 기준

1. 마이크로서비스와 CI 환경에는 Docker를 씁니다.
2. 서로 신뢰하지 않는 사용자의 워크로드에는 가상 머신을 씁니다.
3. 다른 커널이나 OS가 필요하면 가상 머신을 씁니다.
4. 두 방식을 함께 쓰는 구성도 흔합니다. 가상 머신 위에서 컨테이너를 실행합니다.

## 참고

- 이 내용은 일반적인 지식이며, 현재 환경에서 직접 확인한 것이 아닙니다.
- 시작 시간과 크기는 구성에 따라 크게 달라집니다.
- 현재 환경은 WSL2입니다. Docker Desktop을 쓰면 경량 가상 머신 위에서 컨테이너가 실행됩니다.

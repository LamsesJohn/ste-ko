Docker 컨테이너는 호스트 OS의 커널을 공유해서 가볍고 빠릅니다. 가상 머신(VM)은 자체 OS를 통째로 실행해서 무겁지만 격리가 강합니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트 커널을 공유합니다 | VM마다 게스트 OS 커널이 있습니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 보통 수십 초에서 수 분입니다 |
| 크기 | 수십~수백 MB입니다 | 수 GB입니다 |
| 격리 수준 | 프로세스 단위입니다 | 하드웨어 수준입니다 |
| 자원 사용 | 필요한 만큼만 씁니다 | OS마다 CPU와 메모리를 미리 할당합니다 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 가능합니다 | 어떤 OS든 가능합니다 |
| 이식성 | 이미지 하나로 어디서나 같게 실행합니다 | 이미지가 크고 하이퍼바이저에 의존합니다 |

## 용어

- **컨테이너**는 호스트 커널 위에서 격리된 프로세스로 실행하는 애플리케이션 묶음입니다.
- **하이퍼바이저**는 VM을 만들고 실행하는 소프트웨어입니다. 예는 KVM, VMware, Hyper-V입니다.

## 선택 기준

Docker를 고르는 경우:
- 마이크로서비스를 배포합니다.
- CI/CD에서 빠르게 환경을 만들고 지웁니다.
- 개발 환경을 팀원과 똑같이 맞춥니다.

VM을 고르는 경우:
- Windows 서버에서 Linux를 실행하는 것처럼 다른 OS가 필요합니다.
- 신뢰할 수 없는 코드를 실행하거나 멀티테넌트 환경에서 강한 격리가 필요합니다.
- 커널 버전이나 커널 모듈을 직접 제어해야 합니다.

## 함께 쓰는 경우

두 기술은 배타적이지 않습니다. 클라우드에서는 보통 VM을 먼저 만들고, 그 안에서 Docker 컨테이너를 실행합니다. 이렇게 하면 VM의 격리와 컨테이너의 효율을 둘 다 얻습니다.

현재 환경이 WSL2이므로 Docker Desktop은 경량 VM 안에서 Linux 커널을 실행합니다. 이 구성도 같은 방식의 조합입니다.

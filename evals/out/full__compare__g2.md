Docker 컨테이너는 호스트 커널을 공유하는 격리된 프로세스입니다. 가상 머신(VM)은 자체 커널을 가진 OS 전체를 실행합니다. 컨테이너는 가볍고 빠릅니다. VM은 격리가 더 강합니다.

## 구조

- **VM**: 하이퍼바이저(하드웨어를 여러 가상 머신으로 나누는 소프트웨어)가 가상 하드웨어를 만듭니다. 각 VM은 그 위에서 게스트 OS와 커널을 따로 실행합니다.
- **컨테이너**: Docker가 호스트 커널의 기능(namespace, cgroup)으로 프로세스를 격리합니다. 게스트 OS는 없습니다.

## 비교

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트와 공유합니다 | VM마다 따로 가집니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 보통 수십 초에서 수 분입니다 |
| 이미지 크기 | 수십 MB에서 수백 MB입니다 | 수 GB입니다 |
| 자원 사용 | 적습니다 | 게스트 OS 때문에 많습니다 |
| 격리 강도 | 커널을 공유하므로 상대적으로 약합니다 | 하드웨어 수준으로 강합니다 |
| 호스트와 다른 OS | 실행하지 못합니다. 리눅스 컨테이너는 리눅스 커널이 필요합니다 | 실행합니다 |
| 이식성 | 이미지 하나로 어디서나 같게 실행합니다 | 이미지가 크고 하이퍼바이저에 의존합니다 |

수치는 일반적인 범위이며 환경에 따라 다릅니다.

## 선택 기준

- 같은 OS 계열에서 앱을 빠르게 배포하고 확장하려면 컨테이너를 씁니다. 마이크로서비스와 CI가 대표적입니다.
- 서로 신뢰하지 않는 사용자의 코드를 한 호스트에서 실행하려면 VM을 씁니다. 커널 취약점이 모든 컨테이너에 영향을 주기 때문입니다.
- Windows 앱을 리눅스 호스트에서 실행하는 것처럼 다른 OS가 필요하면 VM을 씁니다.
- 둘을 함께 쓰는 경우가 많습니다. 클라우드는 VM 위에서 컨테이너를 실행합니다.

Windows와 macOS의 Docker Desktop도 내부에서 작은 리눅스 VM을 실행합니다. 이 환경에서는 컨테이너가 그 VM의 커널을 공유합니다.

502 오류는 프록시(Nginx, 로드 밸런서 등)가 뒤쪽 앱 서버에서 올바른 응답을 받지 못했다는 뜻입니다. 앱 서버가 살아 있는지부터 확인하십시오.

1. 앱 프로세스가 실행 중인지 확인합니다.
   ```
   systemctl status <앱 서비스 이름>
   ```
2. 프록시를 거치지 않고 앱에 직접 요청합니다.
   ```
   curl -i http://127.0.0.1:<앱 포트>/
   ```
   직접 요청도 실패하면 앱 문제입니다. 성공하면 프록시 설정 문제입니다.
3. 프록시 오류 로그를 읽습니다. Nginx는 보통 `/var/log/nginx/error.log`에 기록합니다. `connect() failed`는 앱이 꺼져 있거나 포트가 다르다는 뜻입니다. `upstream prematurely closed connection`은 앱이 응답 중에 죽었다는 뜻입니다.
4. 앱 로그에서 같은 시각의 오류를 찾습니다. 자주 나오는 원인은 메모리 부족(OOM)으로 인한 종료, 처리되지 않은 예외, 워커 수 부족입니다.
5. 프록시 설정의 upstream 주소와 포트가 앱의 실제 주소와 같은지 확인합니다.
6. 최근 배포나 설정 변경이 있었는지 확인합니다. 있었다면 먼저 되돌려 봅니다.

서버 환경(Nginx, ALB, Cloudflare 등)과 로그 내용을 알려 주시면 원인을 더 좁힐 수 있습니다.

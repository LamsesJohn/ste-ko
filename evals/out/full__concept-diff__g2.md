`merge`는 두 브랜치의 히스토리를 그대로 두고 합치는 커밋을 하나 만듭니다. `rebase`는 내 브랜치의 커밋을 대상 브랜치 끝으로 옮겨 새 커밋으로 다시 만듭니다.

## 비교

| 항목 | `git merge` | `git rebase` |
|---|---|---|
| 히스토리 모양 | 갈라졌다 합쳐지는 그래프 | 일직선 |
| 기존 커밋 | 바뀌지 않음 | 해시가 바뀜 (새 커밋으로 다시 만듦) |
| 병합 커밋 | 만듦 | 만들지 않음 |
| 충돌 해결 | 한 번에 해결 | 커밋마다 해결할 수 있음 |
| 되돌리기 | 병합 커밋 하나를 되돌림 | 어려움 (`git reflog`로 복구) |

## 명령

```bash
# merge: main을 feature에 합친다
git switch main
git merge feature

# rebase: feature의 커밋을 main 끝으로 옮긴다
git switch feature
git rebase main
```

## 선택 기준

- 다른 사람이 이미 받은 브랜치에는 `rebase`를 쓰지 않습니다. 해시가 바뀌면 다른 사람의 로컬 히스토리와 어긋납니다.
- 내 로컬 브랜치를 최신 `main` 위로 정리할 때는 `rebase`를 씁니다. 히스토리가 읽기 쉬워집니다.
- 공유 브랜치에 작업을 합칠 때는 `merge`를 씁니다. 원래 히스토리가 남습니다.

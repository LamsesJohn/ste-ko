`merge`는 두 브랜치의 히스토리를 그대로 두고 합치는 명령입니다. `rebase`는 내 브랜치의 커밋을 다른 브랜치 끝에 다시 쌓아 히스토리를 한 줄로 만드는 명령입니다.

## 동작 차이

| 항목 | `git merge` | `git rebase` |
|---|---|---|
| 히스토리 | 갈라졌다 합쳐지는 모양이 남습니다 | 한 줄로 펴집니다 |
| 커밋 | 기존 커밋을 바꾸지 않고 머지 커밋을 하나 만듭니다 | 내 커밋을 복사해 새 커밋으로 다시 만듭니다. 커밋 해시가 바뀝니다 |
| 충돌 처리 | 한 번에 해결합니다 | 커밋마다 해결할 수 있습니다 |
| 되돌리기 | 머지 커밋 하나를 되돌리면 됩니다 | 이미 push했다면 복구가 어렵습니다 |

## 예시

`feature` 브랜치에서 `main`의 변경을 가져오는 경우입니다.

```
git switch feature
git merge main
```

머지 커밋이 생기고 `feature`의 기존 커밋은 그대로 남습니다.

```
git switch feature
git rebase main
```

`feature`의 커밋이 `main`의 최신 커밋 뒤로 옮겨집니다.

## 선택 기준

- 다른 사람이 이미 가져간 브랜치(공유 브랜치)에는 `rebase`를 쓰지 않습니다. 해시가 바뀌어 다른 사람의 히스토리와 어긋나기 때문입니다.
- 아직 push하지 않은 내 로컬 브랜치를 정리할 때는 `rebase`를 씁니다.
- 작업 이력을 그대로 보존해야 하면 `merge`를 씁니다.
- 선형 히스토리를 원하는 팀은 PR을 합칠 때 `rebase` 또는 squash 방식을 씁니다. 팀 규칙을 먼저 확인합니다.

`rebase` 후에 이미 push한 브랜치를 갱신하려면 `git push --force-with-lease`가 필요합니다. 이 명령은 원격 히스토리를 덮어쓰므로 혼자 쓰는 브랜치에서만 실행합니다.

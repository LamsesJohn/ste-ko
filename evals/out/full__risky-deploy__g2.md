네, 문제가 있습니다. 2단계가 실패하면 서버에 실행할 앱이 남지 않고, 되돌릴 방법도 없습니다.

## 문제

1. **롤백 불가**: 이전 버전을 먼저 지웁니다. 복사가 실패하거나 새 버전에 결함이 있으면 복구할 파일이 없습니다.
2. **서비스 중단**: 서비스가 도는 중에 파일을 지우고 복사합니다. 그 사이 요청이 실패하거나, 일부 파일만 새 버전인 상태로 실행될 수 있습니다.
3. **데이터 손실 위험**: `/srv/app` 안에 업로드 파일, 설정, 로그, SQLite 같은 데이터가 있으면 `rm -rf`가 함께 지웁니다. 확인하지 못했으므로 실제 구조를 점검해야 합니다.
4. **검증 단계 없음**: 재시작 후 정상 동작을 확인하는 단계가 없습니다.

## 권장 절차

릴리스 디렉터리를 버전별로 두고 심볼릭 링크만 바꿉니다.

1. 새 버전을 `/srv/releases/<버전>/`에 복사합니다. 기존 파일은 건드리지 않습니다.
2. 링크를 교체합니다.
   ```
   ln -s /srv/releases/<버전> /srv/app.tmp && mv -T /srv/app.tmp /srv/app
   ```
3. 서비스를 재시작합니다.
4. 상태 확인 URL이나 로그로 정상 동작을 확인합니다.
5. 확인에 실패하면 링크를 이전 버전으로 되돌리고 서비스를 재시작합니다.
6. 오래된 릴리스는 최근 3~5개만 남기고 지웁니다.

설정과 업로드 같은 데이터는 `/srv/shared/`에 두고 각 릴리스에서 링크로 연결합니다. 이렇게 하면 배포가 데이터에 영향을 주지 않습니다.

현재 `/srv/app` 안에 어떤 데이터가 있는지 알려 주시면 디렉터리 구성안을 구체적으로 짜 드리겠습니다.

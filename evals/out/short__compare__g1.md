Docker는 호스트 커널을 공유하는 가벼운 격리 방식이고, 가상 머신은 커널까지 따로 가진 완전한 격리 방식입니다.

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 프로세스 | 전체 운영체제 |
| 커널 | 호스트와 공유 | 게스트가 각자 보유 |
| 시작 시간 | 보통 1초 안팎 | 수십 초에서 수 분 |
| 이미지 크기 | 수십 MB에서 수백 MB | 수 GB 이상 |
| 자원 사용량 | 적음 | 많음 |
| 격리 강도 | 상대적으로 약함 | 강함 |
| 운영체제 선택 | 호스트 커널과 같은 계열만 가능 | 제한 없음 |
| 이식성 | 이미지 한 개로 어디서나 실행 | 하이퍼바이저에 종속되는 경우가 많음 |

## 동작 방식

1. 가상 머신은 하이퍼바이저가 하드웨어를 가상화합니다.
2. 각 가상 머신은 자체 커널과 운영체제를 실행합니다.
3. Docker는 리눅스 커널의 namespace와 cgroup을 사용합니다.
4. namespace는 프로세스, 네트워크, 파일 시스템 시야를 분리합니다.
5. cgroup은 CPU와 메모리 사용량을 제한합니다.

## 선택 기준

| 상황 | 권장 |
|---|---|
| 마이크로서비스 배포, CI/CD, 개발 환경 통일 | Docker |
| 서로 신뢰하지 않는 사용자의 워크로드 분리 | 가상 머신 |
| 다른 운영체제나 커널 버전이 필요한 경우 | 가상 머신 |
| 빠른 확장과 높은 밀집도가 필요한 경우 | Docker |
| 강한 보안 경계가 필요한 규제 환경 | 가상 머신 |

## 함께 쓰는 방식

실무에서는 두 기술을 함께 쓰는 경우가 많습니다. 클라우드 가상 머신 위에서 Docker 컨테이너를 실행하면 두 장점을 모두 얻습니다. Windows와 macOS의 Docker Desktop도 내부에서 가벼운 리눅스 가상 머신을 사용합니다.

이 내용은 일반적인 기술 지식이며, 현재 작업 디렉터리의 환경은 확인하지 않았습니다.

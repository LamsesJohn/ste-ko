문제가 있습니다. 이 절차는 삭제와 복사 사이에 서비스가 끊기고, 복사가 실패하면 되돌릴 방법이 없습니다.

확인한 범위는 말씀하신 3단계뿐입니다. 서버의 실제 구성, 스크립트, `/srv/app` 안의 내용은 확인하지 못했습니다.

**문제점**

| 문제 | 영향 |
|---|---|
| 서비스가 실행 중인데 파일을 먼저 지움 | 재시작 전까지 실행 중인 프로세스와 디스크 상태가 어긋남 |
| 삭제 후 복사 | 복사가 실패하면 앱이 사라지고 롤백할 버전이 없음 |
| `/srv/app` 전체 삭제 | 업로드 파일, `.env`, 로컬 DB, 로그가 있으면 함께 사라짐 |
| 복사 중 부분 상태 노출 | 일부 파일만 새 버전인 상태로 요청을 받을 수 있음 |
| 실패 검사 없음 | 2단계가 실패해도 3단계가 실행될 수 있음 |

**권장 절차 (릴리스 디렉터리와 심볼릭 링크 방식)**

1. 새 버전을 `/srv/releases/<버전>`에 복사한다.
2. 설정과 업로드 같은 영구 데이터는 `/srv/shared`에 두고 링크한다.
3. 새 버전의 의존성 설치와 기본 점검을 서비스 중단 없이 끝낸다.
4. `ln -sfn /srv/releases/<버전> /srv/app`으로 링크를 교체한다.
5. 서비스를 재시작한다.
6. 헬스 체크가 실패하면 링크를 이전 릴리스로 되돌리고 재시작한다.
7. 오래된 릴리스는 최근 3~5개만 남기고 지운다.

스크립트에는 `set -euo pipefail`을 넣어 중간 실패 시 즉시 중단하게 하세요. `rm -rf`에 변수를 쓴다면 빈 값 검사도 넣어야 합니다.

`/srv/app` 안에 영구 데이터가 있는지 알려주시면 디렉터리 구조를 더 구체적으로 제안하겠습니다.

# Docker(컨테이너) vs 가상 머신(VM)

## 핵심 차이
- **VM**: 하이퍼바이저가 하드웨어를 가상화하고, VM마다 **게스트 OS 전체**(커널 포함)를 실행합니다.
- **Docker 컨테이너**: **호스트 OS의 커널을 공유**하고, namespace·cgroup으로 프로세스를 격리합니다.

## 비교표

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 수준 | 프로세스 수준 (커널 공유) | 하드웨어 수준 (커널 분리) |
| 시작 시간 | 보통 1초 이내 | 수십 초 ~ 수 분 |
| 크기 | 수 MB ~ 수백 MB | 수 GB ~ 수십 GB |
| 리소스 오버헤드 | 매우 낮음 | 게스트 OS 때문에 높음 |
| 밀도 | 한 호스트에 수십~수백 개 | 수 개~수십 개 |
| 보안 격리 | 상대적으로 약함 (커널 취약점 공유) | 강함 |
| OS 선택 | 호스트 커널과 같은 계열만 가능 | 다른 OS도 자유롭게 실행 |
| 이식성 | 이미지 기반으로 매우 높음 | 이미지가 크고 무거움 |
| 영속성 | 기본은 일회성, 볼륨으로 보존 | 디스크 상태가 기본적으로 유지 |
| 대표 도구 | Docker, Podman, containerd | VMware, VirtualBox, KVM, Hyper-V |

## 언제 무엇을 쓰나

**Docker가 적합한 경우**
- 마이크로서비스, CI/CD, 개발 환경 통일
- 빠른 배포·스케일링 (Kubernetes 등)
- "내 컴퓨터에선 되는데" 문제 해결

**VM이 적합한 경우**
- 강한 격리가 필요한 멀티테넌트 환경, 보안이 중요한 워크로드
- 다른 OS(예: Linux 호스트에서 Windows) 실행
- 커널 수준 수정이나 레거시 시스템 운영

## 참고
- 둘은 배타적이지 않습니다. 클라우드에서는 **VM 위에 컨테이너를 올리는** 구성이 일반적입니다.
- Windows/macOS의 Docker Desktop은 내부적으로 경량 Linux VM(WSL2 등)을 사용합니다. 지금 환경(WSL2)도 그런 예입니다.
- Kata Containers, Firecracker처럼 컨테이너의 편의성과 VM의 격리를 결합한 기술도 있습니다.

Docker 컨테이너는 호스트 OS의 커널을 공유하는 격리된 프로세스이고, 가상 머신(VM)은 자체 커널을 가진 완전한 컴퓨터를 소프트웨어로 만든 것입니다. 그래서 컨테이너는 가볍고 빠르며, VM은 격리가 더 강합니다.

## 비교

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 커널 | 호스트 커널을 공유합니다 | 게스트 OS가 자체 커널을 가집니다 |
| 격리 수준 | 프로세스 수준입니다 | 하드웨어 수준입니다 |
| 시작 시간 | 보통 1초 안팎입니다 | 보통 수십 초에서 수 분입니다 |
| 이미지 크기 | 수십 MB에서 수백 MB입니다 | 수 GB입니다 |
| 자원 사용 | 앱이 쓰는 만큼만 사용합니다 | OS 전체가 쓰는 자원을 따로 사용합니다 |
| 다른 OS 실행 | 호스트와 같은 커널 계열만 가능합니다 | Windows, Linux 등 어떤 OS도 가능합니다 |
| 보안 | 커널 취약점이 모든 컨테이너에 영향을 줍니다 | 한 VM의 침해가 다른 VM으로 번지기 어렵습니다 |

(수치는 일반적인 경향이며, 환경에 따라 다릅니다.)

## 구조 차이

- VM은 하이퍼바이저(VM을 만들고 관리하는 소프트웨어) 위에서 게스트 OS를 통째로 실행합니다.
- 컨테이너는 호스트 OS 위에서 컨테이너 런타임이 실행합니다. 리눅스 커널의 namespace와 cgroup 기능으로 프로세스를 격리하고 자원을 제한합니다.

## 선택 기준

컨테이너를 고르는 경우:
- 마이크로서비스를 배포합니다.
- CI/CD에서 같은 환경을 빠르게 반복해서 만듭니다.
- 한 호스트에 많은 앱을 밀집해서 실행합니다.

VM을 고르는 경우:
- 호스트와 다른 OS나 커널이 필요합니다.
- 서로 신뢰하지 않는 사용자의 워크로드를 분리해야 합니다.
- 레거시 앱이 OS 전체에 의존합니다.

## 함께 쓰는 방식

많은 조직이 VM 위에서 컨테이너를 실행합니다. VM이 테넌트(사용자 단위)를 분리하고, 컨테이너가 앱을 패키징합니다. Kata Containers나 Firecracker처럼 컨테이너마다 경량 VM을 붙여 두 장점을 합친 기술도 있습니다.

참고로 Windows와 macOS의 Docker Desktop은 내부적으로 리눅스 VM을 실행하고 그 안에서 컨테이너를 돌립니다.

**Docker 컨테이너는 호스트 커널을 공유하는 격리된 프로세스이고, 가상 머신(VM)은 자기 커널을 가진 완전한 OS입니다.** 그래서 컨테이너는 가볍고 빠르며, VM은 격리가 더 강합니다.

## 구조 차이

- 컨테이너: 호스트 OS의 커널을 그대로 씁니다. 커널의 기능으로 프로세스마다 파일, 네트워크, 자원을 분리합니다.
- VM: 하이퍼바이저가 하드웨어를 가상화합니다. 하이퍼바이저는 VM을 만들고 실행하는 소프트웨어입니다. VM마다 게스트 OS와 커널이 따로 돕니다.

## 비교

| 항목 | Docker 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 프로세스 | 전체 OS |
| 커널 | 호스트와 공유 | VM마다 별도 |
| 시작 시간 | 보통 1초 안팎 | 보통 수십 초에서 분 단위 |
| 이미지 크기 | 보통 수십~수백 MB | 보통 수 GB |
| 자원 사용 | 적음 | 많음 |
| 격리 강도 | 상대적으로 약함 | 강함 |
| 게스트 OS | 호스트 커널과 호환되는 것만 가능 | 호스트와 다른 OS도 가능 |

시간과 크기는 일반적인 경향입니다. 실제 값은 이미지와 설정에 따라 다릅니다.

## 선택 기준

- 컨테이너를 고르는 경우: 같은 환경을 빠르게 배포하거나, 마이크로서비스를 많이 띄우거나, CI에서 일회용 환경이 필요할 때입니다.
- VM을 고르는 경우: 신뢰할 수 없는 코드를 돌리거나, 서로 다른 OS가 필요하거나, 테넌트 사이에 강한 격리가 필요할 때입니다.

## 함께 쓰는 경우

두 기술은 겹쳐 쓰는 경우가 많습니다. 클라우드 서비스는 VM 안에서 컨테이너를 실행합니다. Windows와 macOS의 Docker Desktop도 내부에 Linux VM을 두고 그 안에서 컨테이너를 실행합니다.

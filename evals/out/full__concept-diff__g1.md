**merge는 기존 커밋을 그대로 두고 합치는 커밋을 하나 추가합니다. rebase는 내 커밋을 대상 브랜치의 끝으로 옮겨 새 커밋으로 다시 만듭니다.**

## 결과 차이

`main`에서 갈라진 `feature` 브랜치에서 실행하는 경우입니다.

- `git merge main`: 병합 커밋이 생깁니다. 커밋 기록에 분기와 병합이 남습니다.
- `git rebase main`: Git이 `feature`의 커밋을 `main` 최신 커밋 뒤로 옮겨 다시 만듭니다. 커밋 기록이 한 줄이 됩니다.

| 항목 | merge | rebase |
|---|---|---|
| 기존 커밋 | 그대로 유지 | 해시가 바뀐 새 커밋으로 대체 |
| 커밋 기록 모양 | 분기와 병합이 보임 | 한 줄 |
| 충돌 해결 | 한 번 | 커밋마다 나올 수 있음 |
| 공유 브랜치에 사용 | 안전 | 위험 |

## 선택 기준

- 이미 push해서 다른 사람이 받은 브랜치에는 rebase를 쓰지 않습니다. 커밋 해시가 바뀌어 다른 사람의 기록과 어긋납니다.
- 내 로컬 브랜치를 최신 `main`에 맞출 때는 rebase를 씁니다.
- 기능 브랜치를 `main`에 합칠 때는 merge를 씁니다. 팀 정책이 다르면 정책을 따릅니다.

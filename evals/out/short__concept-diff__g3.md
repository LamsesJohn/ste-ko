`git merge`는 두 브랜치의 히스토리를 보존한 채 합치고, `git rebase`는 내 커밋을 대상 브랜치 끝으로 옮겨 히스토리를 한 줄로 만듭니다.

| 항목 | merge | rebase |
|---|---|---|
| 히스토리 | 분기와 합류 지점이 그대로 남음 | 직선 형태로 재작성됨 |
| 새 커밋 | 머지 커밋이 생김 | 머지 커밋이 생기지 않음 |
| 기존 커밋 | 해시가 바뀌지 않음 | 커밋을 새로 만들어 해시가 바뀜 |
| 충돌 해결 | 한 번에 해결 | 커밋마다 해결할 수 있음 |
| 안전성 | 공유 브랜치에도 안전함 | 공유 브랜치에서는 위험함 |
| 되돌리기 | 머지 커밋 하나를 revert하면 됨 | 원래 상태로 되돌리기 번거로움 |

**동작 예시**

`main`에서 `feature`가 갈라진 상태를 가정합니다.

```
A---B---C   main
     \
      D---E   feature
```

`feature`에서 `git merge main`을 실행하면 머지 커밋 `M`이 생깁니다.

```
A---B---C---------M   feature
     \           /
      D---E-----
```

`feature`에서 `git rebase main`을 실행하면 `D`, `E`가 `C` 뒤로 옮겨집니다. 옮겨진 커밋은 `D'`, `E'`로 해시가 바뀝니다.

```
A---B---C---D'---E'   feature
```

**선택 기준**

1. 이미 push해서 다른 사람이 쓰는 브랜치는 merge를 씁니다.
2. 아직 push하지 않은 내 로컬 브랜치를 최신 `main`에 맞출 때는 rebase를 씁니다.
3. 히스토리를 깔끔하게 유지하고 싶으면 rebase 후 fast-forward merge를 씁니다.
4. 합류 시점을 기록으로 남기고 싶으면 `git merge --no-ff`를 씁니다.

**주의점**

공유된 커밋을 rebase한 뒤 `git push --force`를 하면 다른 사람의 히스토리와 충돌합니다. 강제 push가 필요하면 `--force-with-lease`를 쓰세요.

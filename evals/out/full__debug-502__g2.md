502 오류는 게이트웨이가 앱 서버에서 올바른 응답을 받지 못했다는 뜻입니다. 게이트웨이 뒤의 앱 서버부터 확인합니다.

1. 앱 프로세스가 실행 중인지 확인합니다. `systemctl status <서비스명>` 또는 `docker ps`를 실행합니다.
2. 앱 서버에 게이트웨이를 거치지 않고 직접 요청합니다. `curl -i http://127.0.0.1:<포트>/`를 실행합니다. 이 요청도 실패하면 원인은 앱 서버입니다.
3. 게이트웨이 오류 로그를 읽습니다. Nginx는 `/var/log/nginx/error.log`입니다. `connect() failed`나 `upstream prematurely closed`가 있는지 봅니다.
4. 같은 시각의 앱 로그에서 크래시와 재시작을 찾습니다. `journalctl -u <서비스명> --since "10 minutes ago"`를 실행합니다. 메모리 부족으로 프로세스가 강제 종료되는 현상(OOM)도 이 로그에 남습니다.
5. 게이트웨이 설정의 upstream 주소와 포트가 앱이 실제로 듣는 주소와 같은지 비교합니다. 앱이 듣는 포트는 `ss -tlnp`로 확인합니다.

어떤 게이트웨이(Nginx, ALB 등)를 쓰고 있습니까? 알려 주시면 해당 로그 위치와 원인 후보를 좁힙니다.

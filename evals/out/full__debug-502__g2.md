먼저 업스트림 앱(프록시 뒤에서 실제 요청을 처리하는 서버)이 살아 있는지 확인하십시오. 502는 프록시가 업스트림에서 올바른 응답을 받지 못했다는 뜻입니다.

1. 앱 프로세스 상태를 확인합니다. `systemctl status <서비스명>` 또는 `docker ps`를 실행합니다.
2. 프록시를 거치지 않고 앱에 직접 요청합니다. 예: `curl -i http://127.0.0.1:<포트>/`
3. 직접 요청이 실패하면 앱 로그를 읽습니다. 크래시, 메모리 부족(OOM), 시작 실패를 찾습니다.
4. 직접 요청이 성공하면 프록시 오류 로그를 읽습니다. nginx는 보통 `/var/log/nginx/error.log`입니다.
5. 프록시 설정의 업스트림 주소와 포트가 앱이 듣는 주소와 같은지 비교합니다.
6. 배포 직후에 발생했으면 앱이 완전히 시작되었는지, 헬스 체크가 통과하는지 확인합니다.

프록시 로그에서 자주 보이는 메시지는 다음과 같습니다.

| 로그 메시지 | 의미 |
|---|---|
| `connect() failed (111: Connection refused)` | 앱이 꺼져 있거나 포트가 다릅니다. |
| `upstream prematurely closed connection` | 앱이 응답 중에 죽었습니다. |
| `upstream sent too big header` | 응답 헤더가 프록시 버퍼보다 큽니다. |

이 환경에서는 서버에 접근하지 않았으므로 위 내용은 일반적인 점검 순서입니다. 프록시 종류(nginx, ALB, Cloudflare 등)와 로그 한 줄을 알려주시면 원인을 좁히겠습니다.
